# 古文単語330 対応仕様

## 1. 目的・位置づけ

英単語ターゲット1900・英熟語ターゲット1000に加え、「古文単語330」を教材として選択し、既存の単語帳の操作で古文単語を学習できるようにする。

- 本書はアプリ側の追加対応要件を整理したもの。データ作成・書籍からの抽出は対象外。
- 2026-10-31 の要件確認で合意した内容を「確定要件」として記載する。
- 型構成・内部識別子など、実装方法の提案は「実装方針案」として区別する。
- 既存教材の仕様は [spec.md](./spec.md) を維持し、古文教材に関する差分は本書を参照する。
- 本書の要件はアプリに実装済みで、モックデータによるユニットテスト・E2Eで確認している。実データでの確認は [classic-japanese-plan.md](./classic-japanese-plan.md) の Phase 7 で行い、2026-10-31 時点では No.0001〜0214 で確認済み。

## 2. 確定した対応範囲

| 項目 | 初回対応 |
|---|---|
| 教材表示名 | 古文単語330 |
| 教材の番号範囲 | 1〜330（JSON上は `0001`〜`0330`） |
| 学習モード | 単語帳のみ |
| 出題形式 | 見出し語・例文 |
| 出題方向 | 古文 → 現代語のみ |
| 出題対象 | すべて・間違えたものだけ |
| 出題順序 | 番号順・ランダム |
| 正解判定 | 既存同様、回答表示後に学習者が自己判定 |
| 学習履歴・中断・再開・結果・再挑戦 | 対応 |
| POINT | JSONの `points` を表示 |
| 出典 | ページ番号のみ表示。画像は取得しない |
| 補足Markdown | 初回は非対応。古文教材では取得しない |

### 初回の対象外

- 現代語 → 古文の出題。
- 書き取り、例文穴埋め、タイピング、落ち物ゲーム、バトルでの古文出題。
- 書籍画像の取得・表示、音声、読み仮名や品詞など提示形式にない情報の追加。
- 古文入力のIME対応・表記揺れを考慮した自動採点。
- 認証、クラウド同期、オフライン対応、管理画面。
- 既存英語教材の出題・履歴・ゲームルールの変更。

将来のゲーム対応では「見出し語に対応する全ての意味をまとめた選択肢を正解にする」方針が確認済み。ただし、今回は選択肢生成を実装しない。誤答候補・正解の一意性などは将来対応時に別途設計する。

### 3.2 取得要件

- 教材・リポジトリ・ブランチ・パスの設定は [src/config.ts](../src/config.ts) に集約する。
- 一覧取得は GitHub Contents API、JSONの内容取得は GitHub Raw URLを使用する。
- 一覧から選択範囲の4桁番号JSONを対象にし、画像・Markdown・範囲外ファイルを出題対象にしない。
- 古文の新規開始では毎回一覧と対象JSONを取得し、以前取得したデータをキャッシュから再利用しない。HTTP取得は `cache: 'no-store'` とする。
- 取得中の出題用データ保持と、中断再開のためのセッション保存は許容する。保存セッションを新規開始時のデータキャッシュには使わない。
- 同時取得数制限・一時的な通信失敗への再試行は既存の取得処理を活用する。
- `sourcePages[].image` と補足Markdownの取得リクエストは行わない。
- 必須JSONの欠落・番号不一致・形式不正・通信失敗を黙って除外して開始しない。対象番号を含むエラーを利用者に通知し、原因をログで確認できるようにする。
- 取得・検証に失敗した場合は新しいセッションを開始せず、既存の中断データを上書きしない。
- 認証トークンをクライアントへ埋め込まない。

## 4. JSONデータ契約

### 4.1 形式

以下は構造を示すプレースホルダーであり、実際の書籍内容ではない。

```json
{
  "number": "0001",
  "words": ["（見出し語）"],
  "means": [
    {
      "senseNumber": 1,
      "meaning": "（意味・訳語）",
      "examples": [
        {
          "text": "（古文の例文）",
          "translation": "（例文の現代語訳）"
        }
      ]
    }
  ],
  "points": ["（紙面のPOINT欄）"],
  "sourcePages": [
    { "bookPage": 28, "image": "1028.jpg" },
    { "bookPage": 29, "image": "1029.jpg" }
  ]
}
```

### 4.2 項目のルール

| 項目 | 型・必須条件 | 用途 |
|---|---|---|
| `number` | 必須。4桁の文字列、`0001`〜`0330`。ファイル名の番号と一致 | 教材内の単語番号 |
| `words` | 必須。空でない文字列の配列、1件以上 | 見出し語・表記違い |
| `means` | 必須。意味オブジェクトの配列、1件以上 | 意味の一覧 |
| `means[].senseNumber` | 必須。単語内で一意の正整数 | 意味の表示番号・識別 |
| `means[].meaning` | 必須。空でない文字列 | 意味・訳語 |
| `means[].examples` | 必須。例文オブジェクトの配列、空配列可 | 意味に対応する複数例文 |
| `examples[].text` | 例文が存在する場合は必須。空でない文字列 | 古文の例文 |
| `examples[].translation` | 例文が存在する場合は必須。空でない文字列 | 例文の現代語訳 |
| `points` | 必須。文字列の配列、空配列可 | POINT欄 |
| `sourcePages` | 必須。出典オブジェクトの配列、空配列可 | 出典情報 |
| `sourcePages[].bookPage` | 出典が存在する場合は必須。正整数 | 書籍のページ番号 |
| `sourcePages[].image` | 出典が存在する場合は必須。空でない文字列 | 参照画像のファイル名。初回は利用しない |

- 必須配列の省略・`null` と空配列は区別する。情報がない場合は空配列を使用する。
- `senseNumber` は履歴識別にも使用するため、意味の並べ替えによって変更しない。連番である必要はない。
- 意味・例文・POINTの表示順は配列順とし、意味の番号は `senseNumber` を表示する。
- `words` の全要素は、共通の `means` を持つ表記違いとして扱う。表記ごとに異なる意味への対応づけは行わない。
- `examples` が空の意味も見出し語出題には含める。例文出題ではその意味から問題を作らない。
- 古文特有の文字・歴史的仮名遣い・句読点・改行を保持する。英語向けの正規化や文字置換を適用しない。
- JSONの各テキストはプレーンテキストとして表示し、HTMLやMarkdownとして解釈しない。

## 5. 教材選択・出題設定

### 5.1 表示と切り替え

- 教材一覧に「古文単語330」を追加する。既存教材の表示・順序・初期教材は維持する。
- 古文選択中は出題形式を「見出し語」「例文」、出題方向を「古文 → 現代語」と表示する。
- 英語教材では既存の「単語／熟語」「英語 → 日本語」「日本語 → 英語」の表記と動作を維持する。
- 古文選択中は非対応のアクションと「現代語 → 古文」を無効化し、初回非対応である旨を利用者が確認できるようにする。
- 他アクションや逆方向から古文へ切り替えた場合は、単語帳・古文 → 現代語へ変更し、変更した旨を通知する。
- 既存の書き取り選択時の教材制約などによって、古文教材を選択できなくならないようにする。
- ロード中は設定変更・開始の多重実行を防ぎ、取得する教材と保存するセッションが食い違わないようにする。
- UIだけでなく、保存設定の復元・開始処理・直接の画面遷移でも教材の対応範囲を検証する。
- 古文を選択中でも、既存の英語教材の中断セッション・バトル中断データはそのまま再開できる。現在の設定で保存セッションの教材を置き換えない。

### 5.2 番号・問題数

- 開始番号・終了番号は整数で、`1 ≤ 開始番号 ≤ 終了番号 ≤ 330` を満たす。
- 古文への切り替え時は範囲とランダム出題数を330以下へ補正し、開始番号と終了番号の順序を保つ。
- 既存の初期範囲1〜100、ランダム100問、初期教材の英単語ターゲット1900を維持する。
- ランダム出題数は1〜330の整数で、生成した「問題」の抽出数を指定する。単語番号の抽出数ではない。
- 表記違い・複数例文により、330ファイルから330問を超える問題が生成されることは許容する。
- 対象条件で絞り込み → 問題生成 → 並べ替え → ランダム出題数による抽出の順とする。
- 指定数より生成問題数が少ない場合は、全対象問題を重複なしで出題する。
- 番号順では問題数制限を適用しない。保存済み設定にランダム出題数がない場合も、従来どおり全対象問題を出題する。
- 対象問題が0件なら理由を通知し、開始しない。「例文がない」「不正解履歴がない」と取得・形式エラーを区別する。

## 6. 単語帳の出題・回答

### 6.1 見出し語出題

- `words` の各要素を別問題として出題する。
- 問題文は選択された見出し語。意味が複数ある場合は、回答すべき意味の数を併記する。
- 意味の数は `means.length` とし、訳語の句読点や区切りから推測しない。
- 学習者は全ての意味を考え、タップ／クリックで回答を表示して自己判定する。
- 回答には番号、全見出し語、全ての意味、意味ごとの全例文と現代語訳、POINT、出典ページを表示する。
- 意味と例文の対応を保ち、別の意味の例文や訳と組み合わせない。
- 複数見出し語の正解／不正解履歴は個別に保持する。

### 6.2 例文出題

- `means[].examples[]` の各要素を1問として出題する。最初の例文だけに限定しない。
- 問題文は `examples[].text` のみとし、回答を開くまで現代語訳を見せない。
- 見出し語の数によって同じ例文問題を重複生成しない。
- 回答には出題した例文とその `translation` を対で表示し、該当する意味を明示する。
- あわせて番号、全見出し語、全ての意味、POINT、出典ページを確認できるようにする。
- 同じ意味に属する複数例文も、それぞれ独立した正解／不正解履歴を持つ。

### 6.3 共通の表示・操作

- 空の例文欄・POINT欄・出典欄は表示しない。
- POINTは配列順で箇条書き表示する。既存英語教材の `notes` と混同しない。
- 出典は `bookPage` を表示し、同じページの重複表示は避ける。`image` はリンクや画像として表示しない。
- 既存の正解／不正解ボタン、横スワイプ、進捗表示、中断確認を利用する。
- 長い意味・複数例文・POINTはスマートフォンでも折り返して閲覧できるようにする。縦スクロールを正解／不正解スワイプと誤判定しない。

## 7. 履歴・セッション・結果

### 7.1 学習履歴

- 保存先は既存の `idiom-app-history` を使用し、教材・出題形式・方向・出題単位を区別する。
- 英単語・英熟語と同じ番号でも履歴が衝突しない。
- 見出し語と例文、異なる意味、同じ意味の異なる例文の結果が互いを上書きしない。
- 最新の回答結果のみ保持する。「間違えたものだけ」は最新結果が不正解の問題を対象とし、未回答は含めない。
- 全履歴クリアは古文を含む全教材を対象とする。教材・番号範囲指定のクリアは他教材の履歴を残す。
- 既存の英語教材のキーと、教材IDがない旧英熟語履歴の読み取り互換性を維持する。

### 7.2 セッション・設定

- 中断セッションは `idiom-app-session`、出題設定は `idiom-app-settings` を使用する。
- セッションに古文教材ID・出題形式・方向・出題単位の識別情報・表示データ・進捗・判定結果を保存する。
- 再開時は保存された問題順・例文と訳の対応・進捗を復元し、再抽出や最新JSONへの差し替えは行わない。
- 単語帳の保存枠は既存どおり1つとし、教材ごとの複数同時セッションは導入しない。
- 保存済み英語セッションと、教材IDを省略した旧セッションの扱いを維持する。古文セッションへ誤変換しない。
- 復元できない古文セッションや非対応モードの古文セッションは、理由を通知して再開を止める。自動破棄・別教材への読み替えはしない。
- 既存のテーマ、ゲーム難易度、バトルデッキ・バトルセッションの保存形式は変更しない。

### 7.3 結果・再挑戦

- 正解数・不正解数・正解率の分母は単語数ではなく、セッションの生成問題数とする。
- 「間違えたところをやり直す」は、そのセッションで不正解だった問題だけを、例文の識別を保って再出題する。
- 「間違いデータをクリアしてもう一度」は古文の該当番号範囲の履歴をクリアし、既存と同様にセッションの問題集合を再出題する。
- この操作で他教材の履歴を消さない。ランダム問題を再抽出する仕様には変更しない。

[plan.md](./plan.md) には古い保存キー・取得フローも含まれるため、現行コードと本書を優先して追加実装を設計する。既存のキャッシュやContents APIへのフォールバックを全面改修することは今回の要件ではない。古文の追加経路は本書の取得要件を満たすようにする。

### 8.2 設計案と実装時に詰める点

- 教材IDは `classic-japanese-330`、短縮表示は「古文」とする案。
- 古文専用の入力型を定義し、英語・古文を教材種別で判別できるようにする。古文JSONを単に `IdiomData` とみなす型アサーションは行わない。
- 共通表示モデルへ変換する場合も、複数例文、`senseNumber`、POINT、出典情報を欠落させない。最初の例文への縮約は不可。
- 古文方向の内部IDは表示と分離し、`en-to-ja` をそのまま古文に流用しない。既存英語方向と保存値は維持する。
- 教材ごとの対応可否を、選択UI・開始処理・復元処理で共有する。既存ゲーム／バトルの内部経路でも古文を出題しない。
- 履歴キーの具体的な形式は実装時に決めるが、見出し語の識別、および意味の `senseNumber` と例文の識別を含める必要がある。
- 提示形式には見出し語ID・例文IDがない。配列インデックスだけを永続識別に使うと、追加・並べ替えで過去の結果が別問題へ対応してしまう。内容による識別などを検討し、データ更新で履歴が誤対応しない方式を選ぶ。新たなデータ項目が必要な方式を選ぶ場合は追加確認する。
- データリポジトリで書籍本文・POINT・画像を公開する権限の確認はデータ提供側の責任範囲。本対応は公開許諾を判断せず、画像非表示を公開許諾の代替としない。

初回の学習・表示範囲に未回答の要件はない。上記は実装設計および接続・データ検証時に確認する事項である。

## 9. 受け入れ条件・テスト要件

以下をユニットテストとE2Eで確認する。書籍本文を転載せず、構造を再現した独自のテストデータを使用する。

| ID | 確認内容 |
|---|---|
| CJ-01 | 教材一覧に古文単語330が表示され、既存教材・初期教材が維持される |
| CJ-02 | 書き取りや逆方向から古文を選択でき、単語帳・古文→現代語へ変更された旨が表示される |
| CJ-03 | 古文の非対応アクション・逆方向は開始できず、保存設定や直接遷移でも古文ゲーム等を開始しない |
